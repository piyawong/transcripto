# รูปแบบบันทึกการประชุม

ใช้เนื้อหาส่วนสรุปประชุมในเอกสารตัวอย่างเป็นแนวทาง: ข้อชี้แนะเปิดประชุม → วาระ/ผู้รายงาน → หัวข้อย่อยและรายละเอียด → ข้อชี้แนะของผู้บริหาร → งานติดตามท้ายเอกสาร

## ปัญหาที่แก้

- การอ่านประชุมครั้งก่อนเคยถูกนับเป็นวาระปัจจุบัน ต้องดูคำประกาศเริ่ม/จบการอ่านจากทรานสคริปต์
- รายงานยาวเคยเหลือเพียงไม่กี่ประโยค ทำให้เป้าหมาย ตัวเลข และกิจกรรมย่อยหายไป
- โครงเดิมมีเพียง details แบบแบน จึงไม่สามารถแสดงหัวข้อย่อย ย่อหน้า และรายการเรียงเลขในวาระเดียวกัน
- คำถามสั้นระหว่างข้อชี้แนะทำให้ช่วงประธานถูกจัดเป็นถาม-ตอบทั้งช่วง
- วันที่มอบหมายกับกำหนดส่งงานต้องแยกกัน และเก็บผู้มอบหมายเมื่อมีหลายคน

## การสร้างสรุป

1. Gemini อ่านทรานสคริปต์เต็มเพื่อระบุวาระปัจจุบัน ข้อชี้แนะ และรายการติดตามงาน
2. ถ้าเวลาระหว่างบรรทัดแรกกับบรรทัดสุดท้ายตั้งแต่ 45 นาทีขึ้นไป ให้อ่านต้นฉบับของแต่ละช่วงใหม่พร้อมกันไม่เกิน 3 คำขอ เพื่อเขียนรายละเอียด ทุกช่วงยังเรียงตามการอ่านเต็มไฟล์
   ชนิด report/advice/discussion ถูกจำกัดใน response schema ของแต่ละช่วง เพื่อไม่ให้ข้อเสนอแนะที่มีการแจ้งความคืบหน้ากลายเป็นวาระใหม่
3. ตรวจ citation แล้วสร้าง JSON และ TXT โค้ดไม่ส่งเอกสารคำตอบตัวอย่างไปให้โมเดล และไม่เติมข้อเท็จจริงจากตัวอย่างลงในผล

Prompt หลักอยู่ใน api/src/minutes_prompt.txt และคำสั่งอ่านรายช่วงอยู่ใน api/src/minutes_expansion_prompt.txt ใช้ร่วมกับ bench/summarize.py การอ่านเพิ่มมีต้นทุนและเวลาเพิ่มตามจำนวนช่วง หากคำตอบถูกตัดหรือคำขอรายช่วงล้มเหลว จะไม่บันทึกสรุปบางส่วน

## ข้อมูลและการแสดงผล

- report_sections เพิ่มหัวข้อย่อย ย่อหน้า รายการ และการเรียงเลข ข้อมูลเก่าที่ไม่มี field นี้ยังใช้ details
- assigned_on เก็บวันที่มอบหมาย ส่วน due เก็บกำหนดส่งเท่านั้น
- หน้าเว็บและ TXT แสดงโครงเดียวกัน หน้าเว็บมีเวลาอ้างอิงสำหรับเปิดเสียง
- สรุปที่บันทึกไว้แล้วต้องสรุปใหม่เพื่อรับรายละเอียดใหม่
- ความถูกต้องของชื่อยังขึ้นกับทรานสคริปต์ ถ้าชื่อขัดแย้งให้ระบุจุดตรวจสอบ ไม่แก้เป็นชื่อที่โมเดลคุ้นเคยจากบริบท

## ทดลองกับ job ที่มีอยู่

จากโฟลเดอร์ api:

```sh
cargo run --bin summarize_job -- <job-id> ../.run/<new-run-directory>
```

คำสั่งเก็บทรานสคริปต์และผลเดิม แล้วเรียก pipeline จริงโดยไม่ถอดเสียงซ้ำ ผลใหม่อยู่ใน summary.txt, summary.json และ meta.json ตรวจผลก่อนนำไปใช้กับ job:

```sh
cargo run --bin summarize_job -- <job-id> ../.run/<run-directory> --publish-saved
```

การ publish ตรวจว่าทรานสคริปต์และสรุปเดิมยังไม่เปลี่ยน ไม่มี worker กำลังทำงาน และ citation ผ่าน ผลเดิมเก็บใน before.json ของรอบนั้น
